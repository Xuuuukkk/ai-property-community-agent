## 一、产品目标（我们在做什么）

构建一个 **AI Native 的物业社区管理平台**，让业主、物业人员、维修师傅三类角色通过自然语言完成社区业务闭环。

核心价值：

```
业主说一句话 → AI 理解 → 调用业务工具 → 完成任务 → 反馈结果
```

MVP 阶段要验证的四件事：

1. AI 是否能理解物业业务需求
2. Agent 是否能调用业务工具完成动作
3. 系统是否能跑通真实业务闭环
4. RAG 是否能准确回答社区知识问题

## 三、当前核心问题

### 3.1 AI 体验不达标（最高优先级）

当前 Agent 是**规则兜底实现**，`LLM_API_KEY` 为空，没有真正接入 LLM 做生成。

典型表现：

- 用户问"今天有发公告吗"，回答"公告《社区通知》已发布"
- 没有时间理解、没有内容摘要、没有自然语言组织
- RAG 检索后只是把知识片段硬拼，没有 LLM 总结

**根因**：RAG 只有 Retrieval，没有 Generation。意图分类和部分回复生成也走了规则路径。

### 3.2 RAG 检索质量差

当前 embedding 用 `deterministic` fallback（无语义），导致检索召回率低。

### 3.3 其他待完善项

- API 权限颗粒度待细化（目前只有登录 + 角色路由守卫）
- 前端测试 / E2E 测试缺失
- Docker 镜像未自动推送 / 未上云
- 生产环境密码、SECRET_KEY 需替换

## 四、后续工作计划（目标导向）

### 阶段一：AI 体验攻坚（未来 1-2 周，最高优先级）

目标：**让业主端 AI 助手从"能回答"变成"答得好"**。

| 任务 | 目标 | 验收标准 |
|---|---|---|
| T1.1 接入真实 LLM | 配置 LLM_API_KEY，让 Agent 使用 LLM 生成回复 | 公告查询、知识问答返回自然语言回答 |
| T1.2 公告查询增强 | 支持时间理解、内容摘要、空结果处理 | 问"今天有公告吗"能准确回答有无，并摘要内容 |
| T1.3 知识问答增强 | LLM 基于 RAG 检索结果生成带引用来源的回答 | 回答末尾标注来源文档 |
| T1.4 修复 Agent 体验优化 | 多轮对话更自然，工单创建后信息同步更完整 | 业主能顺畅完成报修全流程 |
| T1.5 评估数据集更新 | 补充 AI 体验相关评估用例 | 评估报告覆盖公告/知识/修复场景 |

### 阶段二：RAG 质量提升（第 2-3 周）

目标：**让知识库问答从"能查到"变成"查得准"**。

| 任务 | 目标 | 验收标准 |
|---|---|---|
| T2.1 接入语义 Embedding | 换用 sentence-transformers 或云端 embedding API | Recall@5 ≥ 70% |
| T2.2 优化知识库切片 | 调整 chunk 大小、重叠、metadata | 检索结果更相关 |
| T2.3 索引重刷与验证 | 重新索引知识库，跑评估脚本 | 评估指标提升 |

### 阶段三：工程加固（第 3-4 周）

## 五、本次需要你决策的事项

1. **是否接入真实 LLM？**
   - 需要：提供 `LLM_API_KEY`（OpenAI 或兼容接口）
   - 影响：AI 体验会质变，但有 API 成本

2. **Embedding 方案选择**
   - 方案 A：本地 sentence-transformers（需稳定 HuggingFace 访问）
   - 方案 B：云端 Embedding API（如 OpenAI、智谱、讯飞）
   - 方案 C：先接入国产大模型（兼容 OpenAI 接口）

3. **后续优先级确认**
   - 是否先全力攻克 AI 体验，工程加固延后？
   - 还是并行推进？
