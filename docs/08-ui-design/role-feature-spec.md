# 三端功能清单（供 UI 外包使用）

> 本文件只描述功能、页面、信息字段和交互操作，不涉及视觉风格、配色、排版、动效。
> 外包设计师/前端可基于此文档进行页面设计和实现。

---

## 1. 项目概述

系统名称：云溪花园智慧社区 Agent

三个用户角色：

| 角色 | 英文 | 系统入口 |
|---|---|---|
| 业主 | OWNER | `/owner/*` |
| 物业人员 | PROPERTY_STAFF / ADMIN | `/admin/*` |
| 维修人员 | WORKER | `/worker/*` |

统一登录流程：

```
门户 / → 选择角色 → /login → 账密登录 → 按角色进入对应系统
```

---

## 2. 业主端（Owner Application）

目标用户：小区业主
核心目标：提供社区服务统一入口，让业主能报修、查费、看公告、跟踪工单。

### 2.1 首页 `/owner`

信息：
- 小区名称、品牌标识
- 当前登录业主信息：用户名、真实姓名、房屋地址（从 `house_binding` + `house` 表关联）
- 未缴费用总额（从 `fee_bill` 表统计）
- 最近 3~5 条公告（从 `notice` 表查询）

入口：
- AI 社区助手入口 → `/owner/ai`
- 快捷服务入口：报修、查费、公告、我的工单

### 2.2 AI 社区助手 `/owner/ai`

功能：
- 文本输入框，发送自然语言消息
- 消息列表：用户消息 + 助手回复
- 助手消息中可能包含：工单编号、费用金额、公告列表、操作确认
- 快捷指令或示例（可选）："我家厨房漏水"、"查一下物业费"、"最近有什么通知"

数据来源：
- `POST /api/agent/chat`：发送 `{ message, user_id }`
- 响应：`{ intent, response, tool_results, requires_human }`

### 2.3 报修服务 `/owner/repair`

功能：
- 提交新报修工单
- 查看历史报修工单列表

提交工单字段：
- 问题类型（下拉选择）：水电维修、家电维修、门窗维修、墙面/地面、公共设施、其他
- 问题描述（多行文本）
- 房屋地址（自动带出当前业主绑定房屋，可切换）
- 紧急程度（单选）：高 / 中 / 低
- 图片上传（可选，MVP 可不做）

工单列表字段：
- 工单编号
- 问题描述摘要
- 当前状态
- 创建时间
- 更新时间

数据来源：
- 提交：`POST /api/repair/orders`
- 列表：`GET /api/repair/orders?owner_id={user_id}`

### 2.4 费用查询 `/owner/fees`

功能：
- 查看当前业主的费用账单列表
- 查看未缴费用总额
- 查看逾期费用（如有）

账单字段：
- 账单周期
- 费用类型：物业费、停车费、水费、电费、燃气费等
- 应缴金额
- 缴纳状态：已缴 / 未缴 / 逾期
- 截止时间
- 缴费按钮（MVP 可只做标记，不接入真实支付）

数据来源：
- `GET /api/fees/bills?owner_id={user_id}`

### 2.5 社区公告 `/owner/notices`

功能：
- 公告列表，按时间倒序
- 公告详情查看
- 公告类型筛选（全部 / 停水停电 / 社区活动 / 设施通知 / 安全通知）
- 置顶公告优先显示

公告字段：
- 标题
- 类型标签
- 发布时间
- 内容正文
- 发布人

数据来源：
- `GET /api/notices/`

### 2.6 我的工单 `/owner/tickets`

功能：
- 全部工单列表（维修工单）
- 按状态筛选：待处理 / 处理中 / 已完成 / 已关闭
- 工单详情

列表字段：
- 工单编号
- 问题描述
- 当前状态
- 维修人员姓名（如已分配）
- 创建时间

详情字段：
- 工单完整信息
- 状态变更时间线
- 维修人员联系方式（可选）

数据来源：
- `GET /api/repair/orders?owner_id={user_id}`

### 2.7 我的 `/owner/profile`（可选）

功能：
- 显示用户信息：头像、用户名、真实姓名、手机号、角色
- 显示绑定房屋信息：楼栋、单元、房号
- 退出登录

数据来源：
- `GET /api/auth/me`
- `GET /api/users/{user_id}/houses`

## 3. 物业管理端（Property Admin System）

目标用户：物业工作人员、管理员
核心目标：管理工单、用户、公告，掌握社区运营数据。

### 3.1 首页 Dashboard `/admin`

信息：
- 今日新增报修数
- 处理中工单数
- 已完成工单数
- 待处理工单数
- 未缴费用总额（可选）
- 最近公告（可选）

数据来源：
- 聚合 `repair_order` 表状态统计
- 聚合 `fee_bill` 表

### 3.2 工单管理 `/admin/repairs`

功能：
- 工单列表，支持按状态、日期、楼栋筛选
- 工单详情查看
- 分配维修人员
- 修改工单状态
- 关闭工单

列表字段：
- 工单编号
- 业主姓名 / 房屋地址
- 问题描述
- 紧急程度
- 当前状态
- 分配维修人员
- 创建时间

操作：
- 查看详情
- 分配人员（从维修人员列表选择）
- 状态变更：待处理 → 已分配 → 处理中 → 已完成 → 已关闭

数据来源：
- `GET /api/repair/orders`
- `PATCH /api/repair/orders/{id}/assign`
- `PATCH /api/repair/orders/{id}/status`

### 3.3 用户管理 `/admin/users`

功能：
- 业主列表
- 维修人员列表
- 物业人员列表
- 房屋列表
- 用户-房屋绑定关系

业主列表字段：
- 用户名
- 真实姓名
- 手机号
- 绑定房屋
- 注册时间

维修人员列表字段：
- 用户名
- 真实姓名
- 手机号
- 工种 / 技能标签
- 工作状态

物业人员列表字段：
- 用户名
- 真实姓名
- 手机号
- 角色

数据来源：
- `GET /api/users/`
- `GET /api/workers/`

### 3.4 公告管理 `/admin/notices`

功能：
- 公告列表
- 发布公告
- AI 辅助生成公告草稿
- 编辑 / 删除公告
- 置顶 / 取消置顶

发布公告字段：
- 标题
- 内容
- 公告类型
- 是否置顶
- 发布时间（立即 / 定时）

AI 辅助：
- 输入一句话，如"明天停水维修"
- 调用 `POST /api/agent/chat` 生成标题和正文
- 人工审核后发布

数据来源：
- `GET /api/notices/`
- `POST /api/notices/`
- `DELETE /api/notices/{id}`

### 3.5 费用管理 `/admin/fees`（可选）

功能：
- 账单列表
- 生成账单
- 标记缴费状态

数据来源：
- `GET /api/fees/bills`
- `POST /api/fees/bills`

### 3.6 设置 / 退出登录

功能：
- 显示当前登录物业人员信息
- 退出登录

## 4. 维修人员端（Worker Application）

目标用户：维修工人
核心目标：接收任务、更新进度、完成维修。

### 4.1 任务首页 `/worker`

信息：
- 今日任务数
- 待接单数
- 处理中数
- 已完成数

入口：
- 今日任务列表
- 全部任务
- 我的

### 4.2 任务列表 `/worker/tasks`

功能：
- 按状态筛选：待接单 / 处理中 / 已完成
- 任务卡片列表

任务卡片字段：
- 工单编号
- 业主姓名
- 房屋地址
- 问题描述
- 紧急程度
- 当前状态
- 创建时间 / 期望完成时间

数据来源：
- `GET /api/repair/orders?worker_id={user_id}`

### 4.3 任务详情 `/worker/tasks/{id}`

信息：
- 工单编号
- 业主信息（姓名、手机号、房屋地址）
- 问题类型
- 问题描述
- 紧急程度
- 当前状态
- 创建时间
- 状态变更历史

操作：
- 接单（状态：ASSIGNED → ACCEPTED）
- 开始维修（ACCEPTED → PROCESSING）
- 完成维修（PROCESSING → COMPLETED）
- 添加维修记录 / 备注（可选）

数据来源：
- `GET /api/repair/orders/{id}`
- `PATCH /api/repair/orders/{id}/status`

### 4.4 我的 `/worker/profile`

功能：
- 显示维修人员信息
- 今日/本周完成工单统计
- 退出登录

数据来源：
- `GET /api/auth/me`
- `GET /api/repair/orders?worker_id={user_id}`

## 5. 公共说明

### 5.1 登录与认证

- 所有子系统页面需登录后才能访问
- 未登录用户访问 `/owner/*`、`/worker/*`、`/admin/*` 会被重定向到 `/login`
- 角色不匹配会被重定向到门户 `/`
- Token 有效期 7 天，存储在 localStorage
- API 请求头：`Authorization: Bearer {token}`

### 5.2 工单状态定义

```
CREATED      # 已创建
ASSIGNED     # 已分配维修人员
ACCEPTED     # 维修人员已接单
PROCESSING   # 维修中
COMPLETED    # 已完成
CLOSED       # 已关闭
```

### 5.3 用户角色定义

```
OWNER           # 业主
PROPERTY_STAFF  # 物业普通员工
ADMIN           # 物业管理员
WORKER          # 维修人员
```

### 5.4 关键 API 汇总

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/auth/login` | POST | 登录，返回 token + 用户信息 |
| `/api/auth/me` | GET | 获取当前登录用户 |
| `/api/agent/chat` | POST | AI 助手对话 |
| `/api/repair/orders` | GET/POST | 工单列表 / 创建工单 |
| `/api/repair/orders/{id}` | GET | 工单详情 |
| `/api/repair/orders/{id}/assign` | PATCH | 分配维修人员 |
| `/api/repair/orders/{id}/status` | PATCH | 更新工单状态 |
| `/api/fees/bills` | GET | 账单列表 |
| `/api/notices/` | GET/POST | 公告列表 / 发布公告 |
| `/api/users/` | GET | 用户列表 |
| `/api/workers/` | GET | 维修人员列表 |

## 6. 给外包的备注

1. **不需要设计的内容**：视觉风格、配色、字体、圆角、阴影、动画。这些由 image2 或外包设计师决定。
2. **必须保留的内容**：每个页面需要展示的信息字段、可执行的操作、页面之间的跳转关系。
3. **移动端优先**：业主端和维修人员端主要使用手机；物业端主要使用桌面端。
4. **表单字段已完整列出**：外包只需设计如何输入，不需要增删字段。
5. **角色隔离**：三个端入口不同，但共享登录态。设计时可考虑是否使用底部 Tab（移动端）或左侧导航（桌面端）。
