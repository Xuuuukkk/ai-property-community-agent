# database/ — Alembic migrations

Per technical-design V2.1, Alembic lives in the top-level `database/` directory
(not inside `backend/`). The ORM models live in `backend/app/models/`; `env.py`
adds `backend/` to `sys.path` and reads `DATABASE_URL` from the app settings.

## Layout
- `alembic.ini` — config (no hardcoded URL; env.py injects it)
- `env.py` — migration environment, targets `Base.metadata`
- `script.py.mako` — revision template
- `versions/` — migration scripts (autogenerated from Phase 2 onward)
- `init/` — first-boot SQL for the postgres container (enables pgvector)

## Commands
```bash
# from this directory
cd database

# create a migration after changing models (Phase 2+)
alembic revision --autogenerate -m "create core tables"

# apply / inspect
alembic upgrade head
alembic current
alembic history
```

Make sure `DATABASE_URL` points at the target database (see `backend/.env.example`).
